# ハーネスを定期点検する

ハーネスは、放っておくと実態から遅れていく（書いてある手順と実際の手順がずれる、使われない資料が増える、同じ注意が何度も口頭で繰り返される）。これを定期的に見直し、**提案 → 承認 → 反映 → 記録**の順で直す。

機械的な点検の結果:

!`node "${CLAUDE_PROJECT_DIR}/.claude/scripts/harness-check.mjs"`

前回の点検以降のコミット:

!`git -C "${CLAUDE_PROJECT_DIR}" log --oneline -30`

## 1. 材料を集める

- 上の機械的な点検の結果
- 改善案の置き場と、前回の点検の記録（場所は `CLAUDE.local.md`）
- `CLAUDE.md`・`CLAUDE.local.md`・`.claude/skills/*/SKILL.md`・`.github/` のテンプレート・`README.md`
- 前回の点検以降の PR と Issue（`gh pr list --state merged`）: スキルの手順どおりに進んだか、PR 本文は簡潔か、見つかった問題は起票されているか

## 2. 見直す観点

| 観点 | 確かめること |
|---|---|
| 正しさ | 書かれたパス・コマンド・手順・バージョンが実態と合っているか |
| 重複と矛盾 | CLAUDE.md・CLAUDE.local.md・スキル・メモリ・`~/.claude/CLAUDE.md` の間で同じことを二重に書いていないか、食い違っていないか |
| 置き場所 | CLAUDE.md に手順が入り込んでいないか（手順はスキルへ）。特定のファイルだけの規約は .claude/rules/（パスを指定したルール）の方が合っていないか |
| 使われ方 | スキルの手順のうち、毎回飛ばされている・毎回補っているものはないか |
| 不要なもの | 長く更新されていない資料、終わった計画、使われていないスキル・テンプレート |
| 繰り返し | 同じ訂正・同じ説明を何度もしていないか（ハーネスに書くべきこと） |

Claude Code 組み込みの `/doctor prompt-audit` でも、指示の矛盾や古い記述を点検できる。必要ならユーザーに実行を提案する。

## 3. 提案する

- 見つけたことを「直す案」「消す・archive に移す案」「様子を見る」に分けて、**差分つきで**提案する
- 改善案の置き場にたまっている案も、採用・見送りを提案する
- ここで止まり、ユーザーの判断を待つ

## 4. 反映して記録する

- 承認されたものだけを反映する。公開のハーネスの変更は、通常どおり Issue と PR にする
- 見送ったものは、理由とともに改善案の置き場に残す
- 点検の記録に、日付・見つけたこと・反映したことを追記する（次回の点検の起点になる）
- ハーネスの設計に関わる判断は、判断の記録にも残す
